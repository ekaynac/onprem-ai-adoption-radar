# Radar v3 — The On-Prem AI Intelligence Desk

**Date:** 2026-08-04
**Status:** Design for approval
**Supersedes:** the catalog-first information architecture of v2. The v2
platform (canonical store, lineage, significance, rings, capacity
engine, MCP) is retained as the engine room; this spec changes what the
product *is*.
**Sponsor persona:** Mega Bilişim — public calling-card and internal
weapon for on-prem AI consulting.

## 0. The problem with v2, stated honestly

v2 is a well-ranked, well-cited catalog of public data. A catalog of
Hugging Face's data cannot beat Hugging Face, and a trending page
cannot beat trendshift. The user's verdict — "I don't get any
meaningful insight" — is correct because insight was never designed in:
every number on the site is a re-presentation of a number that exists
somewhere else.

The one asset neither HF nor trendshift has is the **capacity engine**
(fit, topology, throughput, launch recipes, power). v2 buried it as a
feature. v3 makes it the front door.

## 1. Identity

> **HF tells you what exists. Trendshift tells you what's rising. The
> Desk tells you what to run, what it costs, and what to do about this
> week's changes — with receipts.**

Decisions made (2026-08-04, with the owner):

- **Audience:** Mega's consulting edge — must impress prospects and
  accelerate engagements.
- **The 30-second job:** *"What should I run?"* — given hardware,
  workload, and policy: which model + engine + quant, at what cost,
  with what launch command.
- **Data stance:** derived/public data only (no GPU bench spend).
  The moat is therefore **triangulation + synthesis + the capacity
  engine + the Mega brand**, not primary measurement.
- **Form factors:** weekly brief + alerts; MCP/API as a first-class
  product; stack-profile dashboard. Trending repos, benchmarks, new
  models, and news are ingested as raw material — never presented as
  the product by themselves.

## 2. The four surfaces

### 2.1 The Answer Machine (front door)

The homepage opens with a question, not a table:

> *What do you want to run?* → task (coding assistant / chat / RAG /
> embedding / vision / speech) → hardware (preset, custom spec, or
> saved profile) → constraints (license policy, min context,
> concurrency, data-locality notes).

Output: a **ranked shortlist of 3–5 candidates**, each with:

1. **Fit** — verdict + topology + best quant from the capacity engine
   (exists).
2. **Capability percentile for the task** — from the aggregated
   benchmark layer (new, §3.1): "84th percentile on coding evals among
   open models ≤34B (Aider 61%, LiveBench-code 43; 3 sources)".
3. **License gate** — pass/fail against the stated policy.
4. **Operational cost** — kW from the engine + a rental-equivalent
   $/month and $/1M-tokens figure so the number is business-legible.
5. **Ecosystem maturity** — engine compat matrix + derivative count +
   tenure (all exist).
6. **Launch recipe** — copyable (exists).

Every answer renders as a **shareable one-page recommendation brief**
with every number cited — the consulting artifact. "Generated by Mega's
On-Prem Intelligence Desk" is the calling-card mechanism.

### 2.2 The Desk (weekly brief + alerts)

Upgrade the digest from "list of changes" to **an analyst brief with
calls**. Structure per item: what happened → what it means for on-prem
operators → verdict (Act / Evaluate / Ignore) → receipts. Sections:

- Model releases that matter (significance-gated, lineage-grouped).
- Benchmark movement (from §3.1 deltas — "X overtook Y on coding evals
  this week").
- Engine & platform changes with operational impact (from §3.2
  classified news: breaking flags, dropped hardware, new kernels).
- Security/license changes (OSV feed exists).
- The week's Answer-Machine spotlight: one worked recommendation.

Published as page + RSS + email-ready HTML. Verdicts are recorded and
**scored publicly over time** ("calls ledger") — synthesis with a
spine; being seen keeping score is itself differentiation.

### 2.3 Stack profiles (the dashboard lens)

Evolve workspaces into a **stack profile**: estate (devices) + running
stack (engine + versions, models in production, quant formats). Then:

- Alerts = news/releases/advisories **diffed against the profile**:
  "vLLM 0.8 removes flag you use / drops sm_80 — Act" vs. silence for
  irrelevant changes.
- The brief personalizes: profile-affecting items float to the top.
- The Answer Machine defaults to the profile's hardware.

Static/public mode ships one **demo profile** (a representative Mega
reference architecture) so the public site demonstrates the mechanism.

### 2.4 MCP/API as product

The Desk's tools become the pitch: "plug Mega's radar into your
assistant." Polish and document: `recommend(task, hardware,
constraints)` (the Answer Machine), `benchmarks(model)`,
`whats_new(stack_profile)`, plus the existing capacity/fit/catalog
tools. The site's docs page markets this explicitly.

## 3. The new data layer (all derived, all cited)

### 3.1 Benchmark aggregation & triangulation

New store `data/benchmarks.jsonl` (append-only, per repo rules):
`{model_id | hf_repo, benchmark, score, unit, source, source_url,
retrieved_at, self_reported: bool}`.

Sources (fixture-tested adapters, enabled one at a time): HF Open LLM
Leaderboard, LMArena (elo), LiveBench, Aider leaderboard, SWE-bench
site, model-card self-reported tables (already parsed as curated
benchmarks). Never a number without a source URL.

**Triangulation is the insight feature:** per model, show independent
vs self-reported side by side and flag gaps ("self-reported 82,
independent mean 74 — Δ8 flagged"). Task-level percentiles (coding,
reasoning, long-context) computed within comparable weight classes feed
the Answer Machine's capability line.

### 3.2 News → change intelligence

New ingestion: RSS/Atom from a curated source list (engine blogs,
vendor blogs, HF blog, r/LocalLLaMA top, HN Algolia search for
llm-infra terms; arXiv exists). Each item passes an **LLM extraction
step with a strict schema** (event_type from the existing intelligence
taxonomy, affected components [engine/model/hardware/quant-format],
operational_impact: breaking|improvement|informational, one-line
summary, citation). Extraction runs in the two-hourly pipeline behind a
budget; items failing schema validation land in the review queue, never
on the site. Raw firehose is browsable ("Newsroom") but the *product*
surfaces only classified, stack-matchable events.

### 3.3 Reuse, not rebuild

Trending repos, model discovery, lineage, significance, rings,
source-health, capacity engine, digest plumbing, MCP server, snapshot
delivery: all retained and repointed at the new surfaces. The catalog
and trending pages remain as **evidence appendix** — every Answer
Machine claim and brief item links down into them. They leave the
primary navigation.

## 4. What dies or is demoted

- The catalog as a homepage concept — demoted to appendix.
- Ring tiles as a headline — rings become one factor inside answers.
- The generic release stream as a default view — the Desk supersedes
  it; the stream stays as the appendix's raw feed.
- Any surface whose content is explainable as "HF/trendshift, re-sorted"
  must either feed an answer, a brief item, or an alert — or be cut.

## 5. Phases

- **D1 — Benchmark layer:** store + 3 source adapters + triangulation
  view + task percentiles; benchmarks section on model detail replaced
  with the aggregated, per-source table. Gate: every displayed score
  cites a source URL; ≥2 independent sources for the top-20 curated
  models; self-vs-independent gaps flagged.
- **D2 — Answer Machine:** the six-component answer (fit, percentile,
  license, cost incl. rental-equivalent $, maturity, recipe) as API +
  MCP `recommend` + question-first homepage; shareable brief page.
  Gate: an answer for the demo profile renders fully cited in static
  mode; golden tests against engine outputs.
- **D3 — The Desk:** brief generator (deltas + benchmark moves +
  classified news → drafted brief with Act/Evaluate/Ignore verdicts) +
  calls ledger + RSS/email HTML. Gate: brief builds from a week of
  fixture data; every verdict carries receipts; ledger persists calls
  append-only.
- **D4 — News/change intelligence:** ingestion + LLM extraction with
  schema validation + review-queue fallback + newsroom appendix. Gate:
  fixture-tested extraction; zero unclassified items on product
  surfaces; budget-bounded.
- **D5 — Stack profiles & alerts:** profile model (estate + stack
  versions), event-vs-profile matcher, alert feed + personalized brief,
  demo profile on the public site. Gate: a fixture profile receives an
  Act alert for a matching breaking change and silence for a
  non-matching one.
- **D6 — MCP/API productization + IA cutover:** homepage flip to
  question-first + Desk; docs/marketing page for MCP; catalog/trending
  demoted to appendix nav. Gate: 30-second job test — from a cold
  visit, a hardware+task question reaches a cited recommendation in
  ≤3 interactions.

Execution rules unchanged from the restoration spec: one phase per PR,
gates enforced, every number cites its source, unknowns stay unknown,
append-only history. LLM-extraction output is always labeled as
machine-extracted and linked to its source.

## 6. Success criteria (the anti-HF test)

Pick any page of the finished product at random. If its content could
be produced by re-sorting HF or trendshift, the page fails review. Every
primary surface must contain at least one of: a recommendation with
receipts, a triangulated comparison not available at any single source,
a stack-aware verdict, or a scored call.
